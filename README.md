# FieldOps — заявки и отчёты о выездах

Веб-система из трёх страниц с общей базой: диспетчер подаёт заявку (номер по городу, `AST-0001`), все следят за ней в списке и карточке, выездной сотрудник закрывает её отчётом с телефона — с фото, видео, геометками и устройствами. Работает как PWA, отчёт можно заполнить и отправить без связи.

| Страница | Адрес | Кто |
|---|---|---|
| Подача заявки | `/tickets/new` | диспетчер, руководитель |
| Список и карточка заявки | `/tickets`, `/tickets/AST-0001` | все (выездной — свои и неназначенные открытые) |
| Отчёт о выезде | `/report` | все |
| Карточка объекта и реестр устройств | `/objects/{id}` | все |
| Справочники | `/admin` | диспетчер (объекты, города), руководитель (всё) |

## Стек

- **Next.js 16** (App Router, TypeScript) — интерфейс и API в одном приложении.
- **PostgreSQL** + Drizzle ORM. Миграции в `drizzle/`.
- **S3-хранилище** (Yandex Object Storage) для фото и видео. Загрузка частями по 5 МБ через сервер (multipart), с докачкой.
- **Вход**: OAuth Google и/или Яндекс ID. Доступ получают только сотрудники из справочника.
- **PWA**: service worker (`src/sw/sw.ts`), черновик и файлы — в IndexedDB, очередь отправки с Background Sync.
- Excel — exceljs, PDF — pdfkit (шрифт DejaVu в `assets/fonts`), карта — Leaflet + OpenStreetMap.

## Локальная разработка (Windows/macOS/Linux, Docker не нужен)

```bash
npm install
cp .env.example .env.local      # DEV_LOGIN=true, SEED_ADMIN_EMAIL=ваша почта
npm run db:local                # отдельное окно: PostgreSQL на порту 54329 (данные в .data/pg)
npm run db:migrate
npm run db:seed                 # 23 города, 399 объектов, справочники, первый руководитель
npm run dev                     # http://localhost:3000
```

С `DEV_LOGIN=true` на странице входа можно войти любым сотрудником из списка без OAuth (в production отключено всегда).

### Проверки

Браузерные тесты используют Playwright с установленным Chrome (`PW_CHANNEL=chrome`) или `npx playwright install chromium`.

## Развёртывание в Yandex Cloud

1. **Managed Service for PostgreSQL** — кластер PostgreSQL 16+, база `fieldops`. Ежедневные бэкапы включены по умолчанию (срок хранения поставьте 7+ дней). Скачайте корневой сертификат и укажите его содержимое в `DATABASE_CA_CERT`, `DATABASE_SSL=true`.
2. **Object Storage** — приватный бакет (без публичного доступа). Сервисный аккаунт с ролью `storage.editor`, статический ключ доступа → `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY`. Для хранения 3+ лет правила удаления не настраивайте.
3. **Compute Cloud** — ВМ (2 vCPU, 4 ГБ) с Docker. Домен направьте на её IP.
4. На ВМ:
   ```bash
   git clone <репозиторий> fieldops && cd fieldops
   cp .env.example .env     # заполнить; STORAGE_DRIVER=s3, APP_URL=https://домен, DOMAIN=домен
   RUN_SEED=true docker compose up -d --build   # первый запуск: миграции + начальные данные
   docker compose up -d                          # последующие обновления: git pull && docker compose up -d --build
   ```
   Caddy сам получит HTTPS-сертификат. Миграции применяются при каждом старте контейнера.
5. **OAuth**. Google: Cloud Console → OAuth client (Web), redirect `https://домен/api/auth/callback/google`; для корпоративного Google Workspace поставьте тип «Internal» и `ALLOWED_EMAIL_DOMAINS=company.kz`. Яндекс ID: oauth.yandex.ru, права «доступ к адресу почты», redirect `https://домен/api/auth/callback/yandex`.

Для хранения данных в Казахстане используйте регион Yandex Cloud в Казахстане (эндпоинт хранилища и регион задаются в `S3_ENDPOINT` / `S3_REGION`).

## Как устроено

- **Нумерация**: счётчик в строке города, `UPDATE … RETURNING` в одной транзакции с созданием заявки — номера не повторяются и не теряются (проверено 20 параллельными заявками). Код города менять нельзя после первой заявки.
- **Статусы**: отчёт «полностью» → «Выполнена», «частично» → «В работе», «повторный выезд» → «Повторный выезд»; «Я на объекте» сразу переводит в «В работе». Все смены пишутся в историю. Отчёт без заявки создаёт заявку «Внеплановый выезд».
- **Неизменность**: API для правки или удаления отчётов нет. Руководитель может только оставить комментарий.
- **Идемпотентность**: ID отчёта генерируется на телефоне; повторная отправка возвращает уже сохранённый отчёт. Файлы загружаются с ID, сгенерированным на телефоне, принятые части повторно не грузятся.
- **Контроль**: сервер хранит своё время получения; расхождение часов телефона > 10 мин, приезд «в будущем» или отметка дальше порога от координат объекта (по умолчанию 500 м, настраивается) помечают отчёт «на проверку».
- **Реестр устройств**: «Установлено» добавляет, «Демонтировано» убирает, «Заменено» меняет старый IP на новый, прочие действия обновляют данные. Смысл действия задаётся в справочнике, поэтому названия можно менять.
- **Файлы** не публичные: `/api/files/{id}` проверяет права и отдаёт S3-ссылку на 5 минут.
- **Время**: в БД UTC, показ в поясе браузера (cookie `tz`), формат `дд.мм.гггг чч:мм`.

## Структура

```
src/app/(app)/        страницы (report, tickets, objects, admin)
src/app/api/          API
src/lib/server/       бизнес-логика: tickets, reports (статусы, реестр), uploads, storage, auth, pdf
src/lib/shared/       общий код клиента и сервера: проверки IP/MAC, поиск, форматы
src/client/           телефон: IndexedDB, очередь отправки, загрузка частями
src/sw/sw.ts          service worker
data/seed.json        23 города и 399 объектов из прототипа
docs/                 инструкции для пользователей
Прототип/             исходники прототипа на Apps Script (референс)
```
